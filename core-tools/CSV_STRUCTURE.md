# Master CSV Structure — `tools/umd_faculty_master.csv`

## Overview

The master CSV consolidates all scraped faculty data from the individual `.db` files into a single flat file. It is generated by running `core-tools/consolidate_to_csv.py`.

**Current stats (as of 2026-04-09):** 938 unique faculty rows.

---

## Columns

| # | Column | Type | Description | Coverage |
|---|--------|------|-------------|----------|
| 1 | `Name` | string | Faculty full name (e.g., "Abed, Eyad H.") | 100% |
| 2 | `email` | string | UMD email address | 99.8% |
| 3 | `phone` | string | Office/lab phone number(s) | 56.7% |
| 4 | `office` | string | Office location (building + room) | 65.7% |
| 5 | `courses_taught` | string | Normalized course list (see format below) | 10.6% |
| 6 | `key_expertise` | string | Bio + research areas combined | 71.9% |
| 7 | `publications` | string | Publication list from profile pages | 11.1% |
| 8 | `department` | string | Department name(s), comma-separated if multiple | 100% |
| 9 | `bio` | string | Raw biographical text from profile page | 60.7% |
| 10 | `extra_info` | string | Remaining structured info not mapped to other columns | 53.5% |

---

## Column Format Details

### `courses_taught`

Normalized to one course per line in `CODE: Title` format:

```
PHYS272: Introductory Physics: Fields
PHYS373: Mathematical Methods for Physics II
ENME610: Engineering Optimization
BIOE331: Biofluids
```

- Course codes have no spaces (e.g., `PHYS272` not `PHYS 272`)
- Department-name prefixes are converted to standard codes:
  - Physics → `PHYS`, Mathematics → `MATH`, Chemistry → `CHEM`
  - Biology → `BIOL`, Astronomy → `ASTR`, Geology → `GEOL`
- Engineering courses keep their original prefix (e.g., `ENCH`, `ENME`, `BIOE`, `ENCE`)
- Cross-listed courses use slash notation: `CHBE491/CHBE691: Title`
- Deduplicated by course code (same course across semesters appears once)
- Lines within a cell are separated by `\n` (newline within the quoted CSV field)

### `key_expertise`

Combined from two sources:
1. The `bio` field (biographical text / research description)
2. `RESEARCH` / `RESEARCH AREAS` / `RESEARCH INTERESTS` sections from `extra_info`

Separated by `\n\n` when both are present.

### `extra_info`

Contains structured sections that were NOT extracted into other columns. Sections use uppercase headers:

```
CURRICULUM VITAE:
https://example.umd.edu/cv.pdf

PERSONAL WEBSITE:
http://example.com

EDUCATION:
Ph.D., MIT 2008

HONORS AND AWARDS:
- 2020: ACM Fellow
```

Common section headers found in this field:
- `CURRICULUM VITAE`, `CV/LINKS`
- `PERSONAL WEBSITE`, `LAB WEBSITE`, `WEBSITE`, `GOOGLE SCHOLAR`
- `EDUCATION`, `APPOINTMENTS`
- `HONORS AND AWARDS`, `MAJOR RECOGNITIONS AND HONORS`
- `NEWS`
- `GRADUATE PROGRAM AFFILIATIONS`
- `PROFESSIONAL EXPERIENCE`, `PROFESSIONAL SOCIETIES`

### `department`

Department affiliation as scraped. Clark faculty may have multiple affiliations comma-separated:

```
Electrical and Computer Engineering, The Institute for Systems Research
```

**Known issue:** Department names are not yet normalized. See `DATA_CLEANING.md` for details.

## Source Databases

The CSV is built from these databases in priority order (first match wins during dedup):

| Priority | Database | Table | Rows | Notes |
|----------|----------|-------|------|-------|
| 1 | `tools/clark_faculty.db` | `clark_faculty` | 185 | Has `office` and `departments` columns |
| 2 | `tools/cmns_faculty.db` | `cmns_faculty` | 566 | Physics, Math, Bio, Chem, Astro, Geo, AOSC, Smith |
| 3 | `tools/cmsc_faculty.db` | `cmns_faculty` | 204 | Computer Science (some overlap with CMNS) |
| 4 | `tools/amsc_faculty.db` | `cmns_faculty` | 175 | Applied Math (heavy overlap with others) |

Deduplication is by **email** (lowercased). Faculty with no email are always included (no dedup possible). 192 duplicates are skipped.

## Regenerating the CSV

```bash
cd core-tools && ../.venv/Scripts/python.exe consolidate_to_csv.py
```

Output goes to `tools/umd_faculty_master.csv`. The script prints coverage stats and per-department counts on completion.

---

## Relationship to OneClique CSV

The upstream consumer is `OneClique/backend/data/umd_faculty.csv`, which uses the same first 8 columns (`Name` through `department`). The master CSV adds `bio` and `extra_info` as columns 9-10. The intent is to merge this master CSV into the OneClique CSV later.
